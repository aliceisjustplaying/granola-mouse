# Wand-pointing prototype spec (THROWAWAY)

Question under test: does one-shot webcam calibration (ArUco on the AMOLED) +
quaternion tracking through a 90° flip give usable absolute pointing, and how
fast does yaw drift?

Two independent pieces build against this spec **in parallel**:
- Proto firmware (fresh ESP-IDF v6.0.2 project at repo root; `main/` +
  `tools/gen_marker.py`) — owns the device and `/dev/cu.usbmodem101`.
- Mac script (`proto/wand_mac/wand_proto.py`) — must NOT touch the serial
  device; develops against replay/synthetic data.

## Serial protocol (device → Mac, USB-Serial/JTAG)

- IMU samples, target ≥200 Hz (never below 100 Hz), one line each:
  `IMU,<t_us>,<gx>,<gy>,<gz>,<ax>,<ay>,<az>`
  - `t_us`: esp_timer microseconds (uint), monotonic
  - gyro in **dps** (float), accel in **g** (float), raw IMU body axes,
    bias-uncorrected (Mac side owns all math)
- One config line at boot, then every 5 s:
  `CFG,gyro_range_dps=<n>,accel_range_g=<n>,odr_hz=<n>`
- Anything else printed must start with `#`.
- Gyro range: ±2048 dps if the component supports it, else the max it does
  (report actual in CFG).

## Marker (on AMOLED)

- ArUco `DICT_4X4_50`, id 0. As built: 320×320 px asset centered on the
  368×448 portrait panel, containing a **240×240 px active symbol** inside
  40 px embedded quiet zones (320 px active + quiet zones cannot fit the
  368 px panel width — original spec was wrong).
- Marker "up" = screen up (away from the USB connector).
- Render at gray level ~200/255 (not full white) on black; no other content.
- Nominal pixel pitch 0.0788 mm/px → active symbol side ≈ **18.9 mm**.
  **Verify with a ruler at first run**; single constant `MARKER_SIDE_MM` in
  the Mac script (set to 18.9).

## Frames & conventions

- Body frame = raw QMI8658 axes as streamed. Mounting orientation on the board
  is unverified → the Mac script MUST expose a 3×3 axis-remap constant and a
  `--probe` mode (live per-axis printout) to determine it empirically.
- Pointing ray in use (device flat in hand): device long axis pointing away
  from the user = screen-up direction, same as marker "up".
- Screen frame: origin at display center, x right, y up, camera assumed at
  top-center of the laptop screen (offset constant in script).

## Mac script (`proto/wand_mac/wand_proto.py`)

Single file, `uv run` with PEP 723 inline deps
(opencv-python, numpy, imufusion, pyserial, pyobjc-framework-Quartz).
Modes:
- default: CALIBRATE (webcam preview, ArUco solvePnP, spacebar captures) →
  TRACK (serial → AHRS seeded with calibration quaternion → forward-ray ∩
  screen plane → `CGWarpMouseCursorPosition`)
- `--replay FILE`: run TRACK from a captured CSV, no hardware needed
- `--fake-calib`: skip camera, assume device facing camera at 0.5 m
- `--probe`: live axis readout for determining the remap matrix
Terminal HUD (~2 Hz): yaw drift °/min while at rest, peak |gyro| seen,
saturation warning at >90% of range, current cursor target.
Webcam intrinsics: approximate from FOV constant (default 65° horizontal),
overridable; good enough for a feel test.

## Proto firmware

- Dedicated minimal firmware — no BLE, no UI, no other features. Reuse
  hardware bring-up from `~/src/a/tinydraw` (see `HARDWARE_NOTES.md`).
- Boot → init display, draw embedded marker (`main/proto_marker.h`, RGB565 C
  array generated by `tools/gen_marker.py` via uv) → init IMU → stream forever.
- Capture ~10 s of live rest-state output to `proto/sample_imu.csv` for the
  Mac script's replay mode (flip capture happens later, during integration).
- Unknown serial lines must be skipped by the Mac parser (boot ROM noise).

## Success criteria (record actual numbers in proto/VERDICT.md)

1. Yaw drift at rest < ~2°/min after the script's software bias calibration.
2. Peak gyro during a brisk flip < 90% of configured range.
3. Post-flip pointing error < ~5 cm at 50 cm distance.
4. Subjective: cursor goes where your brain expects. 🪄

Throwaway code: no tests, no error handling beyond runnable, no abstractions.
